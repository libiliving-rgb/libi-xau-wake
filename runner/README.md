# LiBi XAU: ejecución gratuita independiente del navegador

Repositorio autorizado `libiliving-rgb/libi-xau-wake`, rama `main`, workflow `LiBi XAU Wake`. Linux estándar en repositorio público, sin runners de pago. Cron nominal desplazado a `2-57/5`; no garantiza puntualidad. Se conserva cada intervalo y latencia de barra. No llamar a Floot suspendido, contratar servicios ni ejecutar órdenes.

`model.cjs` es generado desde el código canónico del Site mediante `scripts/build-background.cjs`; manifiesto con huellas por archivo. Fórmulas, pesos, entrada/SL/TP y ciclo originales congelados. biquote es una referencia indicativa MT5, broker no identificado; procedencia por barra y equivalencia con INFINOX desconocidas. Términos permiten uso/almacenamiento en este producto; no publicar el feed bruto. Las barras se validan, se excluyen abiertas, no se rellenan huecos. DXY se construye con seis pares y fechas reales; se excluye hasta disponer de comparación válida. Macro es la copia puntual original y caduca; no vigilancia continua.

El workflow emplea el secreto de Actions ya existente `LIBI_XAU_WAKE_SECRET` como material para cifrar su estado AES-GCM con separación de propósito; nunca lo imprime ni lo extrae de GitHub. Si falta, no reinicia el estado ni genera operaciones. `state/runner.json` guarda el estado cifrado. Cada observación original y evento se archiva cifrado para el Site, con ECDH P-256 + HKDF + AES-GCM, usando solo su clave pública. No hay credenciales ni datos de cuenta en el código. `state/latest.json` es una vista cifrada; la clave privada permanece únicamente en el entorno del Site. Las publicaciones rechazan conflictos de Git en vez de forzar sobrescrituras.

El Site conserva su acceso privado y sincroniza los archivos por revisión monotónica. No cambia de identidad ni sustituye un plan previo activo. Rehidrata archivos pendientes por lotes y marca historial truncado mientras quedan pendientes. Los datos anteriores de Floot siguen pendientes, separados del nuevo registro. El seguimiento ocurre aquí con el navegador cerrado; la sincronización de la vista ocurre al consultarla. Un despliegue o workflow correcto no demuestra una señal vigente ni notificación puntual.

Push usa conexión sellada persistente independiente del token Site. El 7 de octubre se verificó un dispositivo y una aceptación real del servicio; recepción en teléfono no comprobada. Nunca insertar tokens Site en este repositorio. Tras alta/baja de dispositivo, un agente autorizado actualiza exclusivamente el sobre cifrado state/push-config.json con lease de HEAD. No se reenvían eventos previos ni resultados inciertos. La suscripción del nuevo dominio no es transferible desde Floot.

`node runner/test.cjs` verifica gates, niveles congelados, integridad de cifrado y mercado cerrado sin escribir fixtures a producción. El runner real necesita únicamente los recursos ya autorizados. Artefactos brutos quedan cifrados; nunca subir un volcado sin cifrar de las respuestas del proveedor.


Desde el 7 de octubre el módulo generado incluye V0/V1/V2 y N0 con estados prospectivos y eventos independientes en el estado y archivos cifrados. `node runner/variants-test.cjs` es un gate previo al escritor, junto al test canónico. Las variantes no entran en state.events ni en las reclamaciones push públicas. Variants policy y código congelados se enlazan al scan original; una deriva de parámetros bloquea el ensayo sin reiniciar su historial ni impedir el seguimiento público. No existe promoción automática.
